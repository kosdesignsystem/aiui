# React → Flutter для браузера на Mac

Подготовь укомплектованное Flutter-приложение для самостоятельного тестирования пользователем. Это первый из двух этапов; KOS-версия строится на том же коде и ассетах.

1. Определи корень репозитория, React-источник и существующий Flutter-проект. Пути `src/...`, `app/...` и `rules/...` в инструкциях отсчитываются от корня репозитория. По умолчанию цель — `app/<AppName>/files`; явно заданный путь имеет приоритет.
2. Прочитай [процесс переноса и проверки](references/workflow.md) и [правила оригинальных ассетов](references/assets.md).
3. Перенеси выбранные экраны, состояния, сценарии, стили, данные, шрифты и ресурсы. Сохрани существующие KPA-файлы. Браузер и будущий KOS используют общую реализацию экранов и логики; платформенные операции изолируй в адаптерах.
4. Создай `files/assets-manifest.json` по [формату реестра](references/assets.md#реестр-и-проверка-файлов) и выполни `scripts/verify_assets.py` из каталога этого скилла. Для извлеченных inline SVG отдельно проверь сохранение геометрии по разметке: контрольная сумма этого не доказывает.
5. Выполни доступные анализ, web-сборку, браузерный запуск и проверку сценариев. Визуальное сравнение и сравнение скриншотов не выполняй.
6. Передай проект, инструкцию запуска на Mac и результаты проверок. Укажи демо-адаптеры и непроверенные функции.

Переноси оригинальные SVG побайтно; inline SVG извлекай механически. Не заменяй иконки аналогами, генерацией, перерисовкой или растеризацией. Сохраняй параметры SVG и привязку цветов к состояниям.

Приложение должно быть укомплектовано уже на этом этапе. Не откладывай перенос существующих экранов, поведения или ресурсов до KOS-упаковки и не создавай отдельную реализацию для браузерного демо. Используй `rules/minimal_flutter` как основу совместимости, сохраняя код приложения при добавлении web-платформы.

Обычный экспорт во Flutter завершается передачей браузерной версии пользователю. KOS-адаптацию выполняй по соответствующему запросу с помощью [flutter-to-kos](../flutter-to-kos/SKILL.md). При явном запросе обоих этапов выполни их последовательно, сохранив браузерный результат. Недоступные проверки указывай явно.
