# Оригинальные ассеты для обоих этапов

Эти правила обязательны при переносе в браузерный Flutter и при последующей KOS-адаптации. Визуальное сравнение и сравнение скриншотов не выполняй.

1. Составь реестр реально используемых ассетов, включая ресурсы общих компонентов, состояний и анимаций. Пути, способ переноса и контрольные суммы сохраняй в `files/assets-manifest.json` по формату ниже. В README опиши использование, форматы и извлечение inline SVG, сославшись на реестр без дублирования контрольных сумм. Отдельные файлы копируй побайтно; SHA-256 оригинала и копии должны совпадать.
2. SVG-иконки копируй из `src/assets/icons`, иконки приложений — из `src/assets/app_icons`, остальные ресурсы — из фактического источника. Учитывай выбор файла в исходном компоненте: например, приоритет PNG перед SVG в `src/ui/AppIcon.tsx`.
3. Для `src/ui/Icon.tsx` находи исходный SVG по имени иконки. `src/generated/icons` используй для сопоставления с исходником, а не как повод нарисовать иконку заново.
4. Если SVG существует только inline в JSX, sprite или data URI, извлеки его в `.svg` механически. Сохрани исходные пути и структуру; для sprite перенеси необходимые `defs` и ссылки. В реестре запиши место происхождения и способ извлечения. Для извлеченных SVG проверяй соответствие исходной разметке и геометрии; побайтовое совпадение с JSX не требуется.
5. Сохраняй `viewBox`, `path d`, `fill`, `stroke`, толщину и окончания линий, `fill-rule`, `clip-rule`, opacity, transforms, gradients, masks, clip paths и связи с `defs`. Не оптимизируй и не упрощай геометрию во время переноса.
6. Сохраняй параметры показа из React/CSS: размеры, пропорции, fit, выравнивание и цвета для состояний. `currentColor` и CSS-переменные разрешай через соответствующие Flutter-токены на уровне загрузки/рендеринга. Не меняй оригинал ради подстановки цвета; не перекрашивай многоцветную иконку целиком одним фильтром.
7. Для отображения SVG используй Flutter SVG-рендерер, например совместимую с целевыми SDK версию `flutter_svg`. Зафиксируй версию и проверь поддержку используемых SVG-возможностей. Зависимость для точного воспроизведения исходных SVG обоснованна.
8. Запрещено заменять исходные иконки на Material/Cupertino Icons, emoji, символы шрифта, похожие библиотечные иконки, результат генерации или ручную перерисовку через `CustomPainter`/`Canvas`. Автоматическая растеризация SVG в PNG также не является точным переносом исходного ассета.
9. Если рендерер не поддерживает SVG, сохрани оригинал, укажи конкретную неподдерживаемую конструкцию и ищи совместимый способ отображения. Не подменяй ресурс молча; изменение исходного формата или изображения возможно только по явному указанию пользователя.
10. Изображения и другие файловые ресурсы также копируй без перегенерации. Переноси оригинальные шрифты и начертания с регистрацией в `flutter.fonts`. Если формат шрифта не поддерживается, найди исходный TTF/OTF того же семейства и начертания либо явно зафиксируй недоступность; не подменяй шрифт похожим.
11. Все runtime-ресурсы должны находиться внутри `files/assets`. Изображения и SVG явно перечисляй в `flutter.assets`, шрифты — в `flutter.fonts` в `files/pubspec.yaml`. Не оставляй загрузку из `src/web`, `src/assets`, локального Vite-сервера или случайных внешних URL.

## Реестр и проверка файлов

Сохраняй JSON с `version: 1` и массивом `assets`. Одна запись соответствует одному целевому файлу:

| Поле | Значение |
| --- | --- |
| `kind` | `copy` для побайтовой копии; `extracted-svg` для механически извлеченного SVG |
| `source` | Путь исходного файла относительно корня репозитория |
| `target` | Путь внутри `assets/` относительно Flutter-каталога `files` |
| `sha256` | SHA-256 целевого файла, зафиксированный на первом этапе; для `copy` это также SHA-256 оригинала |
| `source_sha256` | Для `extracted-svg`: SHA-256 исходного JSX, sprite или другого файла-контейнера |
| `origin` | Для `extracted-svg`: компонент, symbol ID или другой точный указатель на извлеченный фрагмент |

Контрольные суммы вычисляй из реальных файлов, сохраняя все 64 шестнадцатеричных символа. Если ресурсов нет, массив может быть пустым; объясни это в README. Копирование SVG, PNG и шрифтов использует одинаковый режим `copy`.

Из корня репозитория запусти:

```sh
python3 .agents/skills/web-to-flutter/scripts/verify_assets.py \
  "app/<AppName>/files/assets-manifest.json" \
  --repo-root . \
  --app-root "app/<AppName>/files"
```

Скрипт использует стандартную библиотеку Python 3.9+ и только читает файлы. Код завершения `0` означает совпадение перечисленных ресурсов с реестром, `1` — расхождение или недоступный ресурс, `2` — некорректный вход. Он не создает и не исправляет эталонные суммы.

Проверь комплектность реестра отдельно по использованию ресурсов в коде и регистрации в `pubspec.yaml`: скрипт не обнаруживает забытые записи. Для извлеченного SVG проверка хеша подтверждает неизменность файлов после фиксации; сохранение геометрии и разметки при извлечении проверяй по исходному фрагменту без визуального сравнения.

## Применение на втором этапе

Используй тот же реестр и тот же скрипт. Не извлекай и не генерируй ресурсы заново. Сверяй файлы с зафиксированным состоянием первого этапа; не обновляй контрольные суммы ради прохождения проверки. Если пользователь изменил исходники или выбрал другую входную версию, явно зафиксируй причину и новый состав ресурсов.

Проверь поддержку используемых SVG-конструкций рендерером в KOS-окружении. Если оно недоступно, пометь проверку как невыполненную. Успешная проверка контрольных сумм сама по себе не подтверждает совместимость рендерера.
