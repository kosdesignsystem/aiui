# VoiceHelper

Маршрут: `/#/app/VoiceHelper/main`. Тестовое приложение для **реального**
распознавания русской речи через [GigaAM](https://github.com/salute-developers/GigaAM).
Браузерный SpeechRecognition и заранее записанные ответы не используются.

## Запуск

Нужны Python 3.10+, `uv`, `ffmpeg`, Node.js/npm и несколько ГБ свободного места.
По умолчанию используется CPU; окружение и модель хранятся вне checkout,
в `/workspace/.voicehelper` (можно изменить `VOICEHELPER_RUNTIME_DIR`).

Из корня репозитория:

```bash
bash services/voicehelper/setup.sh
bash services/voicehelper/start.sh
```

В другом терминале:

```bash
npm ci
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

Откройте VoiceHelper в меню. Дождитесь статуса «Модель готова», нажмите
«Начать запись», разрешите доступ к микрофону и говорите. «Остановить»
отключает микрофон и дожидается окончательной расшифровки. Новая запись
заменяет предыдущий текст; итог можно скопировать или очистить.
При уходе с экрана запись останавливается и соединение закрывается.
Для доступа к микрофону нужен HTTPS или localhost.

Первый запуск скачивает `v3_ctc` с
`https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/v3_ctc.ckpt`.
При закрытом доступе к этому домену health endpoint вернёт 503 / `error`,
а кнопка записи будет недоступна. После открытия доступа перезапустите сервис.
Загрузчик GigaAM проверяет опубликованную контрольную сумму модели.
Код GigaAM закреплён на коммите `7447938d791c4f3e643386ee22c33777004293a5`,
лицензия MIT; CPU PyTorch и torchaudio — `2.8.0+cpu`.

## Как работает обновление текста

- AudioWorklet передаёт моно PCM16 по WebSocket каждые 200 мс.
- GigaAM не является нативно потоковой моделью: сервис повторно распознаёт
  текущую фразу примерно через каждые 1,5 секунды полученного аудио.
- Промежуточная гипотеза заменяется, а после паузы около 800 мс фиксируется
  итоговая фраза. Длинная речь разбивается на окна до ~20 секунд с небольшим
  перекрытием — ниже лимита `.transcribe()` в 25 секунд.
- Простая RMS-оценка отделяет тишину; это не полноценный нейросетевой VAD.
  Тихая речь и шум могут влиять на границы фраз и качество.
- Задержка зависит от CPU и длины фразы. Обновление не гарантируется на каждом
  слове. В интерфейсе показано время распознавания последнего фрагмента.
- Один сервис принимает одну запись одновременно, максимум 2 минуты.
  Очередь ограничена; устаревшие промежуточные гипотезы могут пропускаться.

## Размещение

Vite dev и preview проксируют `/voicehelper` на `http://127.0.0.1:8765`.
`VOICEHELPER_SERVER_URL` меняет upstream этого прокси.
Для production нужен Python-сервис и reverse proxy с поддержкой WebSocket.
Один GitHub Pages обслуживает только статические файлы и запускать GigaAM не может.

Если API размещён отдельно, задайте перед сборкой
`VITE_VOICEHELPER_URL=https://ваш-домен/voicehelper`, настройте CORS для health
на своём reverse proxy и `VOICEHELPER_ALLOWED_ORIGINS=https://домен-интерфейса`
для WebSocket. Через обычный Vite/reverse proxy используйте один origin.
Сервис по умолчанию слушает только loopback; публичное размещение требует
собственного контроля доступа и TLS.

Аудио передаётся только в настроенный сервис распознавания. Сберу при работе
отправляется только запрос скачивания весов, а не речь. Аудиофрагменты временно
записываются на сервере в WAV для вызова официального `.transcribe()` и удаляются
сразу после обработки. История текста между перезагрузками не сохраняется.

## Проверки

```bash
UV_CACHE_DIR=/workspace/.voicehelper/uv-cache uv pip install \
  --python /workspace/.voicehelper/venv/bin/python pytest==8.4.2 httpx==0.28.1
/workspace/.voicehelper/venv/bin/python -m pytest -q services/voicehelper/test_server.py
npm run build
curl http://127.0.0.1:8765/voicehelper/health
```

Тесты Python проверяют сегментацию и транспорт с внедрённым тестовым обработчиком,
не точность GigaAM. Для проверки самой модели после её загрузки используйте
микрофон или официальный `example.wav` из GigaAM CDN. Реальное распознавание
считайте проверенным только после получения расшифровки от загруженной модели.

Компоненты интерфейса: `FlowPage`, `List`, `Cell`, `Button`, `Icon` из существующей
дизайн-системы. Новые визуальные компоненты и локальные стили не понадобились.
