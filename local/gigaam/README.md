# Непрерывная диктовка на Mac с GigaAM

Звук с микрофона браузера обрабатывается **на этом же компьютере**: AudioWorklet → WebSocket на `127.0.0.1` → Silero VAD → GigaAM `v3_e2e_ctc`. Текст появляется во время речи. Python остаётся локальным сервером; аренда сервера и облачный API не нужны.

## Первый запуск на Mac с Apple Silicon

Нужны Homebrew, Git, Node.js 20+, Python 3.11 и ffmpeg:

```bash
brew install git python@3.11 node ffmpeg
git clone --branch member/AE https://github.com/kosdesignsystem/aiui.git aiui-local-gigaam
cd aiui-local-gigaam
GIGAAM_PYTHON=python3.11 bash scripts/start-gigaam.sh
```

Если эта папка уже скачана и вы следовали старой инструкции с `git switch --detach b5dfa...`, переключитесь обратно на актуальную ветку:

```bash
cd aiui-local-gigaam
git switch member/AE
git pull --ff-only origin member/AE
GIGAAM_PYTHON=python3.11 bash scripts/start-gigaam.sh
```

При наличии собственных изменений Git может остановить переключение/обновление. Не применяйте `reset --hard`; сохраните изменения или используйте новую папку.

Первый запуск скачает зависимости, веса GigaAM (~442 МБ) и токенизатор. Silero VAD поставляется в Python-пакете. Дождитесь `GigaAM + Silero ready on cpu — continuous dictation`, затем откройте:

**http://localhost:8765/#/app/Notes/main**

Нажмите микрофон и разрешите доступ. Говорите, делайте паузы, продолжайте: через 20 секунд микрофон не выключается. Повторное нажатие завершает запись и уточняет последнюю фразу. Удаление, включая удержание и физический Backspace/Delete в поле заметки, отменяет текущую диктовку; поздний результат не возвращает удалённые слова. Черновик сохраняется в localStorage браузера. Скрытие вкладки останавливает запись.

Терминал должен оставаться открытым. Остановка сервера — Control+C. Для следующего запуска без переустановки и пересборки:

```bash
cd aiui-local-gigaam
.venv-gigaam/bin/python local/gigaam/stream_server.py
```

После обновления кода повторите полный запуск через `scripts/start-gigaam.sh`, чтобы обновились зависимости и интерфейс. Можно задать `--port 8766 --threads 2`; по умолчанию используется CPU и 4 потока PyTorch. На Intel Mac этот набор зависимостей нативно не поддерживается; Rosetta не подходит.

## Как устроено распознавание

- AudioWorklet формирует моно PCM16 LE, 16 кГц, пакетами по 128 мс. Если фактическая частота AudioContext отличается, используется потоковый ресемплинг с сохранением фазы. Основной путь — браузерный AudioContext 16 кГц.
- Silero VAD 6.2.0 анализирует кадры по 32 мс. Начало речи получает до 256 мс предыдущего звука; пауза около 704 мс завершает фразу. Порог входа 0.5 / продолжения 0.35. Это стартовые параметры, их нужно проверить на микрофоне пользователя, шуме и тихой речи.
- Каждые ~0.9 с новой речи создаётся предварительная гипотеза текущего фрагмента. Существует только одна выполняемая обработка и одна последняя ожидающая гипотеза; устаревшие ожидающие гипотезы заменяются. Реальная частота отображения зависит от скорости компьютера.
- Завершённые по паузам фразы закрепляются. При непрерывной речи без пауз сегмент ограничен примерно 12 секундами; сохраняются 2 секунды перекрытия, граница закрепления находится в его середине. Слова сопоставляются по временным меткам их середины; одинаковые слова не удаляются сравнением строк. Качество на границах требует проверки: временные метки и сам текст модели могут ошибаться.
- Завершённые фрагменты имеют приоритет над предварительными. Очередь ограничена 8 фрагментами; при перегрузке диктовка завершается с сообщением. Браузер также ограничивает неподтверждённое аудио тремя секундами, чтобы не накапливать неограниченный хвост.
- GigaAM загружается один раз. Вычисления выполняются вне HTTP-цикла. PCM обрабатывается в памяти через тот же `forward` / `_decode(..., word_timestamps=True)`, что использует закреплённая версия GigaAM. Временные WAV и запуск ffmpeg для каждого фрагмента не нужны.
- Повторное распознавание сегментов — **имитация потокового вывода поверх непотоковой модели**, без кэша энкодера. WebSocket — транспорт, а не потоковая модификация GigaAM. Silero определяет участки речи, GigaAM преобразует их в текст; понимание смысла и команды не реализованы.
- Ответ `partial` содержит всю текущую диктовку и поле `committed`; `done` — всю окончательную диктовку. UI заменяет текущую гипотезу, а не дописывает её повторно. При ошибке показанный текст сохраняется, нераспознанный хвост может быть потерян; аудио для восстановления не сохраняется.
- Одновременно разрешён один сеанс, чтобы не делить состояние VAD и CPU между вкладками. Завершение уже начатого инференса при отмене ожидается до допуска следующего сеанса; его текст отменённому клиенту не возвращается.

## Два варианта приложения

`scripts/start-gigaam.sh` собирает интерфейс с `VITE_NOTES_ASR=local`, выбирая локальный транспорт. В этом варианте ONNX Runtime Web, браузерные веса и Web Speech API не используются. Обычный `npm run build` сохраняет существующий браузерный GigaAM на GitHub Pages. Старый `server.py` с `/api/transcribe` оставлен для совместимости и старых тестов; новый сценарий запускает **stream_server.py**, `/api/stream`.

Сервер слушает только loopback, проверяет Host/Origin, не выводит речь в журнал и не пишет аудио на диск. Интернет нужен при установке и первой загрузке GigaAM; с готовым кэшем диктовка работает локально. Эта инструкция — для браузера на Mac. KOS Mobile → Mac по сети потребует отдельного защищённого подключения; встроенная в KPA модель — другая конфигурация.

## Проверки

```bash
.venv-gigaam/bin/python -m unittest discover -s local/gigaam -p 'test_*.py' -v
node --test local/gigaam/stream-client.test.mjs
VITE_NOTES_ASR=local VITE_BASE_PATH=/ npm run build
```

Настоящие веса, VAD и WebSocket, без подставной модели:

```bash
curl -L https://raw.githubusercontent.com/salute-developers/GigaAM/7447938d791c4f3e643386ee22c33777004293a5/example.wav -o /tmp/gigaam-example.wav
.venv-gigaam/bin/python local/gigaam/smoke_streaming.py /tmp/gigaam-example.wav
```

Smoke-тест сначала проверяет настоящую GigaAM на принудительных границах длинного фрагмента, затем передаёт запись трижды с паузами в реальном темпе (>30 с), проверяет появление текста до остановки, отсутствие лимита 20 с и финальный результат. Контрольный файл — техническая проверка, не оценка точности русской диктовки. Проверки в среде разработки выполняются на Linux CPU; скорость и доступ к микрофону конкретного Mac требуют проверки на этом Mac. Общий `tsc` репозитория содержит ранее существовавшие ошибки в других приложениях; новые файлы проверяются отдельно, сборки Vite проверяются для обоих движков.

Исходники и лицензии: [GigaAM (MIT)](https://github.com/salute-developers/GigaAM), [Silero VAD (MIT)](https://github.com/snakers4/silero-vad), [aiohttp (Apache-2.0/доп. лицензии в пакете)](https://github.com/aio-libs/aiohttp). GigaAM закреплён на ревизии `7447938d791c4f3e643386ee22c33777004293a5`; зависимости — `requirements.txt`.

Проверено при внедрении: 11 Python-тестов, 6 клиентских/AudioWorklet-тестов; реальная диктовка по WebSocket 37 с (первый текст ~1.2 с в тестовой среде); браузер Chromium с микрофонным WAV-источником → AudioWorklet → GigaAM, запись >20 с, остановка, удаление во время диктовки и сохранение черновика. Обе сборки Vite проходят. Проверка не подтверждает скорость Mac или KOS-устройства.
