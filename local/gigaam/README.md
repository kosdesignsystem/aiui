# Заметки с локальным GigaAM

Заметки используют **настоящий GigaAM `v3_e2e_ctc`**, запущенный локально через официальный Python-пакет. Web Speech API не используется. Старый файл `speech.ts` оставлен в репозитории для сохранения существующих файлов, но больше не импортируется приложением.

## Быстрый запуск

Нужны Git, Node.js 20+, Python 3.10–3.13 (рекомендуется 3.11), ffmpeg и совместимый с PyTorch компьютер. На Mac с Apple Silicon зависимости можно установить через Homebrew:

```bash
brew install python@3.11 node ffmpeg
git clone --branch member/AE https://github.com/kosdesignsystem/aiui.git
cd aiui
GIGAAM_PYTHON=python3.11 bash scripts/start-gigaam.sh
```

Если репозиторий уже скачан, не клонируйте его поверх существующей папки: обновите ветку `member/AE`, перейдите в папку проекта и выполните последнюю команду.

Скрипт создаёт отдельное окружение `.venv-gigaam`, устанавливает зависимости, собирает сайт и запускает локальный сервис. При первом запуске GigaAM скачивает веса (~442 МБ для выбранной модели) и токенизатор; Python/PyTorch требуют дополнительного места. Не закрывайте терминал.

Откройте **http://localhost:8765/#/app/Notes/main**. Дождитесь строки `GigaAM v3_e2e_ctc ready on cpu` в терминале, затем нажмите микрофон. Загрузка модели может занять несколько минут. Если нажать раньше, интерфейс попросит дождаться загрузки.

На Windows запускайте команды вручную в PowerShell:

```powershell
py -3.11 -m venv .venv-gigaam
.venv-gigaam\Scripts\python -m pip install torch==2.6.0 torchaudio==2.6.0 --index-url https://download.pytorch.org/whl/cpu
.venv-gigaam\Scripts\python -m pip install -r local/gigaam/requirements.txt
npm ci
npm run build
.venv-gigaam\Scripts\python local/gigaam/server.py
```

Git, Node.js, Python и ffmpeg должны быть установлены и доступны в PATH. Современный PyTorch не предоставляет актуальные колёса для macOS на Intel; для такого компьютера нужен совместимый Linux/Windows либо отдельно подготовленное Linux-окружение. Не обещаем нативный запуск на Intel Mac этим скриптом.

## Сценарий проверки

1. Нажать микрофон и разрешить доступ к микрофону компьютера.
2. Говорить до 20 секунд; повторное нажатие завершает запись раньше. По достижении лимита запись завершается автоматически.
3. Пока показано «GigaAM распознаёт запись…», браузер ждёт результат локальной модели. Текст появляется **после обработки записи**, а не пословно во время речи.
4. Повторная диктовка дописывает заметку. Удаление, в том числе удержанием, стирает текст. Удаление во время записи/ожидания отменяет сеанс и игнорирует поздний ответ; CPU-вычисление уже принятого запроса на сервере может закончиться в фоне.
5. Черновик сохраняется в браузере. Остальные клавиши демонстрационные. Скрытие вкладки или уход с экрана отменяет запись/ожидание.

## Что где работает

- Браузер получает микрофон через `getUserMedia` и формирует моно WAV PCM16.
- `local/gigaam/server.py` обслуживает сайт и `/api/*` на одном локальном адресе. Нет HTTPS → localhost переходов, CORS-настроек и отправки аудио внешнему сервису.
- ffmpeg приводит запись к 16 кГц, затем вызывается `gigaam.load_model('v3_e2e_ctc', device='cpu', fp16_encoder=False)` и `model.transcribe(...)`.
- Временные аудиофайлы удаляются после запроса. Текст и аудио не записываются в журналы приложения.
- Интернет нужен для установки зависимостей и первой загрузки весов. При наличии всех зависимостей, весов и токенизатора распознавание выполняется локально.
- Сервис слушает только `127.0.0.1`; запросы с чужими Host/Origin отвергаются. Не предназначен для публичного размещения.
- На GitHub Pages виден тот же экран, но диктовка отключена с подсказкой запустить локальную версию. GitHub Pages модель не запускает.

Другая модель/порт: `bash scripts/start-gigaam.sh --model v3_ctc --port 8766`. Для уже настроенного окружения можно без переустановки и пересборки: `.venv-gigaam/bin/python local/gigaam/server.py`. Опция `--device cuda` предназначена для отдельно установленного и проверенного CUDA/PyTorch окружения.

## Проверки

Проведён реальный smoke-тест на Linux CPU: официальный `example.wav` длительностью 11,29 секунды отправлен через HTTP API, ffmpeg преобразовал запись, GigaAM `v3_e2e_ctc` вернул непустой русский текст. В этой среде вызов модели занял 0,615 с (без загрузки весов); это не прогноз скорости на другом компьютере и не оценка WER. Проверены PyTorch/torchaudio 2.6.0 CPU и ревизия GigaAM из requirements.

```bash
python3 -m unittest discover -s local/gigaam -p test_server.py -v
node --test local/gigaam/client.test.mjs
npm run build
```

API-тесты используют явную подставную модель: проверяют загрузку/ошибки, формат WAV, ресемплинг ffmpeg, очистку файлов и запрет чужого Origin. Они не проверяют качество GigaAM. Для проверки настоящей модели запустите локальный сервис и надиктуйте контрольную фразу. Можно также отправить моно PCM16 WAV до 20 секунд:

```bash
curl -H 'Content-Type: audio/wav' --data-binary @test.wav http://localhost:8765/api/transcribe
```

Ответ содержит `text`, `model`, `device`, `inference_seconds`. Официальный исходный код: https://github.com/salute-developers/GigaAM (MIT); используемая ревизия зафиксирована в `local/gigaam/requirements.txt`.

Клавиатура — общий компонент `src/ui/Keyboard.tsx`; состояние `processing` блокирует повторный запуск микрофона до ответа. Внешний вид основан на исходных скриншотах; полная карта Pixso не была доступна без входа.
