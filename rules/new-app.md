# Добавление нового приложения (new-app)

Используй этот документ, когда приложения еще нет в `src/web`.

## Обязательный порядок

1. Создай структуру приложения в плоском виде:
   1. `src/web/<AppName>/index.tsx`
   2. `src/web/<AppName>/<screen-id>.tsx` (отдельный файл на каждую страницу)
   3. при необходимости `src/web/<AppName>/<screen-id>.scss` рядом со страницей
2. Не создавай папки `screens`, `theme`, `widgets` внутри `src/web/<AppName>`.
3. Перед реализацией страниц примени `component-first`:
   1. Проверь возможности `src/ui`.
   2. Проверь паттерны соседних приложений `src/web/*`.
   3. Сопоставь макет с уже существующими компонентами.
   4. Сначала собери страницу на существующих компонентах.
4. Если возможностей `src/ui` не хватает, остановись и запроси выбор пользователя:
   1. Расширить `src/ui` (обратно совместимо).
   2. Использовать локальные кастомные стили/разметку в `src/web/<AppName>`.
5. После выбора пользователя реализуй страницу(ы).
6. Обнови `src/web/registry.ts`:
   1. каждая страница приложения должна быть зарегистрирована отдельной записью в `screens`;
   2. `id` страницы в registry должен соответствовать имени файла страницы.
7. Если в задаче есть новые компоненты/шаблоны/ассеты/анимации, дополнительно выполни `rules/new-asset.md`.

## Ограничения

1. Не дублируй существующие `src/ui`-компоненты локальными аналогами без выбора пользователя на шаге 4.
2. Не редактируй чужие приложения, если задача про создание нового.

## Чеклист

1. Новое приложение создано в `src/web/<AppName>`.
2. Каждая страница вынесена в отдельный файл и отражена в `src/web/registry.ts`.
3. Папки `screens`, `theme`, `widgets` не создавались.
4. При дефиците функционала получен явный выбор пользователя.
5. Учтены базовые рамки устройства `360x800`, верхний отступ `40`, нижний `52`.
