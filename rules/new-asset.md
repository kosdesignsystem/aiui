# Изменение существующего web-приложения и добавление UI-артефактов (new-asset)

Используй этот документ для любых изменений в существующих web-приложениях (`src/web`), а также при добавлении компонентов, шаблонов, ассетов и анимаций.

## 1. Определи целевое приложение и экран

1. Если экран указан явно, работай только в целевом экране.
2. Если указано приложение без экрана, работай в этом приложении и при необходимости добавь новый экран.
3. При добавлении экрана обнови `src/web/registry.ts`.

## 2. Обязательный процесс component-first

1. Проверь готовые компоненты и стили в `src/ui`.
2. Проверь паттерны соседних приложений в `src/web/*`.
3. Сопоставь элементы требуемого интерфейса с существующими компонентами.
4. Собери первый вариант страницы только на существующих компонентах и паттернах.

Запрещено начинать с кастомной разметки и локальных стилей, пока не выполнены шаги 1-4.

## 3. Обязательная развилка при нехватке функционала

Если существующих возможностей недостаточно, AI обязан остановиться и запросить выбор пользователя:

1. Вариант A: расширить библиотеку `src/ui` с обратной совместимостью.
2. Вариант B: использовать локальные кастомные стили/разметку в целевом приложении.

До явного выбора пользователя нельзя продолжать реализацию.

Рекомендуемая формулировка:
"Для точного UI не хватает возможностей существующих компонентов. Выбираем путь: 1) расширить `src/ui`, 2) сделать локальный кастом в этом приложении?"

## 4. Правила по типам изменений

### 4.1 Компоненты

1. Компоненты общего назначения добавляй или расширяй в `src/ui`.
2. Локальные вспомогательные компоненты держи в `src/web/<AppName>` рядом со страницей (`<screen-id>.tsx`, `<screen-id>.scss`, при необходимости `*.parts.tsx`).
3. Не используй и не создавай папки `screens`, `theme`, `widgets` внутри web-приложения.
4. Не дублируй существующие `src/ui`-компоненты.

### 4.2 Шаблоны

1. Переиспользуемые шаблоны добавляй в `src/templates`.
2. Используй нейтральные названия по задаче, например `SwipeDelete.tsx`.

### 4.3 Ассеты

1. Иконки: `src/assets/icons`.
2. Иконки приложений: `src/assets/app_icons`.
3. Шрифты: `src/assets/fonts` и обновление `src/styles/fonts.scss`.

### 4.4 Анимации

1. Добавляй в `src/animate`.
2. Обновляй `src/animate/README.md` при добавлении новой анимации.

## 5. Ограничения

1. Не обходи развилку из раздела 3.
2. Не смешивай этот процесс с миграцией во Flutter, если запрос был только на синхронизацию.

## 6. Чеклист перед завершением

1. Целевое приложение и экран выбраны корректно.
2. Component-first выполнен.
3. При дефиците функционала получен явный выбор пользователя.
4. Изменения внесены только в целевые файлы.
5. Каждая новая/обновленная страница вынесена в отдельный файл и отражена в `src/web/registry.ts`.
